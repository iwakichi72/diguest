# Diguest — MVP仕様

## MVPの定義

「Ollamaで動くローカルWebアプリが、1セッションの思考掘り下げ対話を行い、Markdownとして手元に保存・再読できる」状態をMVPとする。

DiguestのMVPは、多機能なチャットアプリではない。ユーザーが自分の言葉を置き、AIが問い・整理・仮説を中心に返し、最後に1つのMarkdownファイルとして結晶化するところまでを対象にする。

## 現在の実装前提

- Next.js 16 App Router
- React 19
- TypeScript
- Tailwind CSS 4
- Ollama HTTP API
- ローカルファイルシステム保存（デフォルト: `~/diguest/`）
- DBなし、外部APIなし、シングルユーザー前提

## 機能スコープ

### In Scope（MVP）

#### セッション開始

- ホーム画面から新規セッションを開始できる
- `/session/new` で「今日、何を掘りますか？」に答える
- テーマ未入力では開始できない
- テーマは `/session?theme=...` に渡される

#### 対話エンジン

- `/api/chat` がOllama `/api/chat` へストリーミング接続する
- システムプロンプトはサーバー側で注入する
- 対話履歴はセッション中のReact stateで保持する
- AIは次のいずれかを中心に返す
  - 深掘りする問い
  - ユーザー発言の整理
  - 「こういうことかもしれない」という仮説
- 必要な場合は、短い示唆や確認を添えてよい
- AIは次の振る舞いを主目的にしない
  - アドバイスを連続して出す
  - ユーザーの考えを良い・悪いで評価する
  - 行動を急がせる
  - 一般的な情報提供だけで応答を終える

#### セッション終了

- 対話画面の「ここで終える」から終了できる
- 終了時に `/api/generate-markdown` でMarkdownを生成する
- 要約生成に失敗しても、対話ログだけでMarkdownを生成する
- 保存前にMarkdownプレビューを表示する
- ユーザーが保存すると `/api/save-markdown` でファイルへ書き込む
- 保存後は `/notes/[fileName]` でノートを表示する

#### Markdown生成・保存

- ファイル名フォーマット: `YYYYMMDD_HHMMSS_<テーマ>.md`
- 保存先: `~/diguest/` または設定値で変更可能
- 同名ファイルがある場合は `-2`, `-3` のように連番を付ける
- ファイル名はパストラバーサルできないよう検証する
- MarkdownはUTF-8で保存する

#### ノート再読

- ホーム画面に直近ノートを表示する
- `/notes/[fileName]` で保存済みMarkdownをレンダリング表示する
- Markdownをコピーできる

#### 設定

- 環境変数または `~/diguest/config.json` で以下を設定できる
  - `OLLAMA_BASE_URL`
  - `OLLAMA_MODEL`
  - `NOTES_DIR`
- `~/diguest/config.json` は環境変数より優先される

### Out of Scope（MVP以降）

- 複数ユーザー対応
- DB保存
- 外部AI API連携
- クラウド同期
- PDF・共有エクスポート
- タグ・カテゴリ管理
- ダッシュボード・統計・ストリーク
- AIによる過去ノート自動参照
- 一般的なチャットUI（吹き出し、アバター、提案チップ等）

## Markdownフォーマット仕様

```markdown
---
date: 2024-01-15T10:30:00.000Z
theme: <ユーザーが入力したテーマ>
model: <使用したOllamaモデル名>
turns: <ユーザー発言数>
---

# <テーマ>

## 対話の要約

<AIが生成するセッション全体の要約>

## 掘り出されたもの

- <AIが構造化した思考・発見・仮説>

## 対話ログ

**You:**

<ユーザー発言>

---

**Diguest:**

<AI発言>

---
_Generated by Diguest_
```

## システムプロンプト設計

```text
あなたはDiguestです。ユーザーの思考を掘り下げる対話相手です。

あなたの基本姿勢：
- ユーザーの発言に対して深掘りする問いを返すこと
- ユーザーの発言を構造化して反射すること
- 「こういうことを言いたいのかもしれない」という仮説を提示すること

あなたが主目的にしないこと：
- アドバイス・提案・改善案を次々に出すこと
- ユーザーの考えを良い・悪いで裁くこと
- 行動を急がせること
- 情報提供だけで応答を終えること

必要な場合は、短い示唆や確認を添えてよい。ただし、ユーザー自身の言葉を引き出すことを優先する。

応答は簡潔に。問いは1つずつ。
```

## MVPで特に守ること

### 1. ログだけでも必ず残す

ローカルモデルは要約生成に失敗することがある。要約や「掘り出されたもの」が空でも、対話ログは必ずMarkdownに含める。ログの保存は要約より優先する。

### 2. 助言を主役にしない

Diguestの価値は「答えを出すこと」ではなく「問いを返すこと」にある。必要な示唆は許容するが、便利な提案機能や行動推奨を中心にすると、ユーザー自身の言語化が脇に追いやられる。

### 3. ノートを管理対象にしすぎない

保存済みノートは、検索・分類・達成管理の対象ではなく、静かに再訪するための地層として扱う。MVPでは直近表示と単体表示に留める。

## MVP後の優先候補

1. 月別ノート一覧
2. Ollama接続状態と再試行導線
3. セッション中の下書き保護
4. 設定確認・編集画面
5. 問いのモード設計
