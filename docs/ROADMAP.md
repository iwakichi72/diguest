# Diguest — 機能ロードマップ

## 方針

Diguestは、機能量ではなく「問いの質」と「残るノートへの信頼」で価値を出す。便利な管理機能を増やすより先に、ローカルで静かに掘り、確実にMarkdownとして残る体験を固める。

優先順位は次の順で判断する。

1. AIが助言を主役にせず、問い手として機能しているか
2. セッション内容が失われないか
3. ローカル環境のつまずきが減るか
4. 保存されたノートを静かに再訪できるか
5. UI Briefの禁止事項に触れないか

## MVP補強

### 1. 月別ノート一覧

**狙い:** 保存済みノートを「管理」ではなく「眺めて再訪」できるようにする。

**内容:**
- `/notes` を追加する
- 月ごとにノートをグルーピングする
- 表示情報は日付とテーマに絞る
- 検索、タグ、ターン数、文字数は出さない

**ユーザー価値:** 残した思考の地層を静かに見返せる。

### 2. Ollama接続状態と再試行導線

**狙い:** ローカルAI環境のつまずきを最小化する。

**内容:**
- 起動時にOllama URL、モデル名、接続状態を確認する
- 未起動時は「Ollamaが見つかりません」と具体的に表示する
- 「もう一度試す」を置く
- モデル未pullなど、Ollamaからのエラー本文が取れる場合は短く表示する

**ユーザー価値:** 原因が分からないまま内省が止まることを減らす。

### 3. セッション中の下書き保護

**狙い:** リロード、戻る、ブラウザクラッシュで対話が失われるリスクを下げる。

**内容:**
- セッション中のテーマ、開始時刻、messagesを一時保存する
- DBは使わず、まずは`localStorage`または一時Markdownファイルで検討する
- 保存済みノートとは明確に分ける
- セッション終了後、下書きは削除する

**ユーザー価値:** 長く掘っている最中も安心できる。

### 4. 設定確認・編集画面

**狙い:** ローカルツールとしての透明性を上げる。

**内容:**
- `/settings` を追加する
- Ollama URL、モデル、ノート保存先を表示する
- `~/diguest/config.json` へ保存する
- 保存後はサーバー再起動なしで反映する

**ユーザー価値:** どのモデルで、どこに保存されているかが分かる。

## 次フェーズ

### 問いのモード

助言の有無を厳密に切り替えるのではなく、問い方の角度を変える。例:

- 静かに整理
- 違和感を掘る
- 創作テーマを掘る
- 価値観を掘る

モード名はUIに強く出しすぎない。セッション開始時の小さな選択肢に留める。

### Markdownテンプレートの最小カスタマイズ

Obsidianや日記用途に合わせて、固定セクション名を少し変えられるようにする。本文を複雑に編集するテンプレートエンジンにはしない。

### モデルプリセット

Ollamaモデルを「速い」「深い」「日本語安定」のような使い心地で選べるようにする。プリセットは設定画面に置き、セッション画面には持ち込まない。

### 軽い索引

検索バーではなく、テーマ一覧や最近開いたノートのような控えめな再訪導線を検討する。ノートを管理対象にしすぎない。

## 採用しない方向

### セッション間の自動記憶

過去ノートをAIが自動で読む機能は、`1セッション1ファイル` と `過去ファイルを読まない` という制約に反する。やる場合でも、ユーザーが明示的にノートを選ぶ形に限定する。

### 達成管理

連続利用日数、目標回数、バッジ、スコアは、内省を評価対象に変えてしまう。UI Briefの「ダッシュボード化しない」に従い、採用しない。

### アドバイス主体の補助

「次に何をするべきか」「改善案」「おすすめ」を中心にする機能は、Diguestの役割から外れる。必要な示唆は会話の中で許容するが、Diguestは提案者ではなく問い手である。
